# VaultMind Sovereign AI: Comprehensive Repository Architecture & System Summary

An air-gapped, multimodal, multi-turn ReAct cognitive intelligence engine powered by local Ollama models (`Qwen3`, `Gemma3`, `Qwen3-VL`), SentenceTransformers embeddings, sandboxed tool execution, and real-time SSE streaming.

---

## 1. Executive Summary & Core Mission

**VaultMind Sovereign AI** is engineered for high-security, air-gapped enterprise environments where data privacy, zero external cloud dependencies, and verifiable compliance are mandatory.

### Key Capabilities:
- **100% On-Premise Execution**: Zero outbound network traffic, zero external API calls.
- **Dynamic Model Router**: Intelligently routes incoming queries to the optimal local model based on input modalities (text, image, video), reasoning complexity, and VRAM budgets.
- **Cognitive ReAct Agent Loop**: Autonomous multi-turn execution loop (`Prompt -> Route -> Think -> Tool Call -> Tool Evaluation -> Final Response`).
- **Rich Agent Skills Catalog**: pgvector document search, AST-based safe mathematical evaluation, isolated Python sandbox execution, and artifact generation.
- **Real-Time Streaming**: Server-Sent Events (SSE) streaming delivering sub-second token delivery and transparent agent thought visualization.

### Module 3: AI Cognitive Engine (`ai_llms/`)

#### 1. [`model_types.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/model_types.py)
Defines model metadata classes and default configurations:
- **`ModelConfig`** *(Dataclass)*: Container for model parameters (`name`, `ollama_model`, `modalities`, `capabilities`, `max_complexity`, `target_vram_gb`, `context_length`, `temperature`, `tool_calling`, `reasoning`).
- **`ComplexityType`**: Literal type `Literal["low", "medium", "high"]`.
- **Predefined Model Presets**:
  - `QWEN3_4B`: Fast text reasoning (`qwen3:4b`, ~3.2 GB VRAM).
  - `QWEN3_8B`: Deep text reasoning and cross-doc analysis (`qwen3:8b`, ~5.8 GB VRAM).
  - `QWEN3_VL`: Multimodal image/video reasoning (`qwen3-vl:4b`, ~4.5 GB VRAM).
  - `GEMMA3_4B`: Lightweight multimodal text/image (`gemma3:4b`, ~3.8 GB VRAM).
  - `GEMMA3_8B`: Heavy multimodal vision and synthesis (`gemma3:8b`, ~6.2 GB VRAM).

#### 2. [`interface.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/interface.py)
- **`ModelInterface`** *(Abstract Base Class)*:
  - `generate(messages, **kwargs) -> str`: Generate a complete text response.
  - `stream(messages, **kwargs) -> AsyncIterator[str]`: Stream response chunks asynchronously.
  - `supports(capability: str) -> bool`: Query whether a model supports specific capabilities (`text`, `image`, `video`, `tool_calling`, `reasoning`).
  - `model_name() -> str`: Return model identifier.

#### 3. [`ollama_client.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/ollama_client.py)
Implements `ModelInterface` using `ollama.AsyncClient`:
- **`OllamaModel`**:
  - `chat(messages, tools=None, **kwargs) -> dict`: Executes a chat turn with Ollama, passing tools schemas and handling fallback if tool calling is unsupported.
  - `generate(messages, tools=None, **kwargs) -> str`: Returns message content string.
  - `stream(messages, **kwargs) -> AsyncIterator[str]`: Streams generated tokens and thinking chunks (`thinking` and `content`).
  - `supports(capability) -> bool`: Checks capability against model metadata.
  - `model_name() -> str`: Returns configured model name.

#### 4. [`registry.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/registry.py)
Central in-memory store for model metadata:
- **`ModelRegistry`**:
  - `register(config: ModelConfig)`: Registers model config and aliases.
  - `unregister(name_or_tag: str) -> bool`: Removes model by name or tag.
  - `get(name_or_tag: str) -> Optional[ModelConfig]`: Looks up model config.
  - `get_or_raise(name_or_tag: str) -> ModelConfig`: Look up model or raise `KeyError`.
  - `list_models() -> list[ModelConfig]`: Returns list of all registered models.
  - `create_instance(name_or_tag: str) -> OllamaModel`: Instantiates an `OllamaModel` client.
  - `filter_by_modality(modality: str) -> list[ModelConfig]`: Filters models supporting a given modality.
  - `filter_by_vram(max_vram_gb: float) -> list[ModelConfig]`: Filters models fitting within a VRAM budget.

#### 5. [`router.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/router.py)
Dynamic intent and complexity classifier:
- **`RoutingDecision`** *(Dataclass)*: Holds selected `model_config`, `complexity`, `complexity_score`, `modalities`, and `reason`.
- **`DynamicRouter`**:
  - `detect_modalities(media_paths: list[str]) -> set[str]`: Identifies attached image/video formats.
  - `calculate_complexity_score(query: str) -> tuple[ComplexityType, float, list[str]]`: Evaluates query length, multi-question marks, high-complexity keywords (e.g. *compare*, *audit*, *calculate*, *root cause*), and low-complexity keywords.
  - `route(...) -> str`: Returns optimal Ollama model tag.
  - `route_with_decision(...) -> RoutingDecision`: Performs full routing analysis and returns structured decision metadata.

#### 6. [`embedding.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/embedding.py)
Local vector generation for semantic RAG search:
- **`cosine_similarity(vec1, vec2) -> float`**: Pure mathematical cosine distance calculator.
- **`BaseEmbeddingModel`** *(ABC)*: Interface defining `embed_text`, `embed_documents`, `embed_query`, `aembed_text`, `aembed_documents`.
- **`SentenceTransformerEmbedding`**: Local HuggingFace SentenceTransformer wrapper using `all-MiniLM-L6-v2` (384 dimensions, offline compliant).
- **`MockEmbeddingModel`**: Deterministic mock embedding model for isolated testing.

#### 7. [`tools.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/tools.py)
Agent skills catalog and execution environment:
- **`calculate_expression(expression: str) -> dict`**: Safely evaluates math expressions using Python's Abstract Syntax Tree (`ast`) without `eval()`, preventing injection attacks while supporting trigonometric, logarithmic, and power functions.
- **`run_python_sandbox(code: str, timeout_seconds: int = 5) -> dict`**: Executes Python scripts in an isolated subprocess with strict timeouts, memory controls, and output capture.
- **`search_documents(query: str, top_k: int = 3, department: Optional[str] = None) -> dict`**: Performs semantic similarity search against local document store.
- **`get_document_page(doc_id: str, page_number: int) -> dict`**: Fetches exact text content of a specific page for precision reading.
- **`generate_report_file(doc_type: str, title: str, content: str) -> dict`**: Compiles downloadable structured reports (PDF, Word, Markdown, Excel).
- **`ToolRegistry`**: Manages registration, discovery, Ollama tool schema serialization (`get_ollama_tools()`), and async execution (`aexecute()`).

#### 8. [`agent_loop.py`](file:///home/venkatkagitha/Desktop/projectx/vault_mid%20sih/ai_llms/agent_loop.py)
Cognitive Multi-Turn ReAct Reasoning Engine:
- **`AgentCitation`** *(Dataclass)*: Source attribution linking answers to document names, page numbers, and similarity scores.
- **`ToolExecutionRecord`** *(Dataclass)*: Execution log of tool calls, inputs, outputs, and execution durations.
- **`AgentResponse`** *(Dataclass)*: Final structured response object returned to callers.
- **`ReActAgentEngine`**:
  - `_build_initial_messages(...)`: Compiles system prompt, chat history buffer, and user input/media.
  - `_extract_citations(...)`: Automatically extracts and deduplicates citations from retrieval tool outputs.
  - `run(...) -> AgentResponse`: Executes iterative loop: Model -> Tool Calls -> Execute Tools -> Append Results -> Re-prompt Model -> Final Markdown Response.
  - `stream_run(...) -> AsyncIterator[dict]`: Streams SSE events (`route`, `tool_start`, `tool_end`, `token`, `done`) in real-time.

## 4. LLM Memory & Context Management Architecture

The system manages context and memory across multiple tiers:

```
┌────────────────────────────────────────────────────────────────────────┐
│                     TIER 1: SESSION-LEVEL MEMORY                       │
│  Maintained in Frontend State (`sessions` array in `App.jsx`)           │
│  Tracks turn-by-turn user messages and assistant responses             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Injected via `history` payload
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   TIER 2: AGENT REACT IN-LOOP MEMORY                   │
│  Managed by `ReActAgentEngine._build_initial_messages()`               │
│  - System Prompt with Operational Rules                                │
│  - Prior Conversation Turn History                                     │
│  - Current User Query + Attached Media Encoded as Ollama Images        │
│  - Dynamic Tool Calls (`role: assistant`, `tool_calls: [...]`)         │
│  - Tool Output Payloads (`role: tool`, `name: "...", `content: "..."`) │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                  TIER 3: CITATION & ATTRIBUTION MEMORY                 │
│  Extracted by `_extract_citations()` across all ReAct iterations       │
│  De-duplicates source docs: `(document_id, page_number)`               │
│  Attached to final response payload for UI source tracing              │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   TIER 4: MODEL CONTEXT & VRAM BUDGETS                 │
│  - Context Length: 8,192 tokens standard (up to 262k on Qwen3-VL)      │
│  - Temperature: Configured per model (0.2 default for high precision)   │
│  - VRAM Ceiling: Router validates target VRAM before invoking model   │
└────────────────────────────────────────────────────────────────────────┘
```

### Context Buffer Assembly Flow:
1. **Initial System Context**: System instructions specifying air-gap protocols and tool calling expectations are prepended at index 0.
2. **Turn History Injection**: Previous user and assistant dialogue turns are appended to provide conversational continuity.
3. **Multimodal Media Attachment**: If image files are uploaded, their paths are attached directly to the user message according to Ollama's vision schema.
4. **Intermediate Tool Calls & Results**: During the ReAct reasoning loop, each tool call and its JSON-stringified output are appended as `role: assistant` and `role: tool` messages, providing complete working memory for the LLM's next reasoning step.
5. **Deduplicated Citations**: As documents are read, document metadata, page numbers, and similarity scores are stored in an attribution list and returned in the structured `AgentResponse`.

## 5. Air-Gap & Zero-Cloud Security Architecture

To guarantee strict sovereign privacy compliance:

1. **Local Host Binding**: All services bind exclusively to `127.0.0.1` and `0.0.0.0` within the local machine.
2. **Offline Model Cache**: HuggingFace and SentenceTransformers operate in full offline mode:
   ```bash
   export HF_HUB_OFFLINE=1
   export TRANSFORMERS_OFFLINE=1
   ```
3. **Isolated Code Execution**:
   - Math calculations run through an AST visitor that rejects arbitrary code execution.
   - Script execution runs in an isolated subprocess with strict execution timeouts (default 5s) and sandboxed environment variables.
4. **Zero Outbound Telemetry**: No external cloud LLM APIs (OpenAI, Anthropic, Google Cloud) are referenced or used in the execution pipeline.

## 6. How to Run the Complete System

### Step 1: Start Local Ollama Models
Ensure Ollama is running locally with the target models:
```bash
ollama list
# Ensure qwen3:4b, qwen3:8b, qwen3-vl:4b, or gemma3:4b are present
```

### Step 2: Start Backend API Server
```bash
# From workspace root:
PYTHONPATH=. ./venv/bin/python -m uvicorn ai_llms.api:app --host 0.0.0.0 --port 8000 --reload
```
- API Endpoint: `http://localhost:8000`
- Swagger Interactive Documentation: `http://localhost:8000/docs`

### Step 3: Start Frontend Web UI
```bash
cd frontend/sovereign_ai
npm run dev
```
- Web UI: `http://localhost:5173`

### Step 4: Run Automated Test Suite
```bash
# Run all 33 unit tests covering router, registry, tools, embedding, and ReAct loop:
PYTHONPATH=. ./venv/bin/python -m unittest discover -s ai_llms
```
